# 阶段收尾

收尾有四个产出，建议分两个回合：博客（含方法论讲解）一个回合；复盘 + 路线图更新 + 下一阶段预热一个回合。用户只要其中一样时只做那一样。

## 0. 收尾前必做

1. 读 `learning/PROGRESS.md`，确认本阶段每讲状态都是 `passed`，收集债务清单。
2. **重读本阶段全部记录** `learning/records/pN-*.md` 和引用到的 trace。博客里的每个数字都要在这一步找到出处。
3. 读上一阶段的博客（若有）作为风格基线；读学习者自己写过的博客，沿用他已经建立的结构（标题 → 先看成品 → 编号章节各带「结论与发现」→ 还不能上生产 → 写在最后 → 延伸阅读）。
4. 博客写入 `learning/blog/phaseN.md`（或学习者约定的位置）。写之前先读目标文件，已有草稿不能无故丢弃。

## 1. 博客：写法

### 动笔前先回答：这篇文章的一句话是什么

能用一句话说出的论点，所有章节都为它服务。写不出这句话就不要动笔。好论点的三个特征：反直觉、有本阶段的数据支撑、能自然生成章节结构（每节是论点的一个证据）。标题就是这句话。

### 挑证据的优先级

| 优先级 | 类型 | 处理 |
|---|---|---|
| 最高 | 和预期相反的实验结果 | 每个给完整四段：预期 → 数据 → 解释 → 修法 |
| 高 | 一触发必炸但没被测试抓到的 bug | 原样贴错误代码 → 解释语法/机制 → 炸点在哪 → **为什么测试没抓到** → 教训 |
| 低 | 正常工作的功能 | 一小段代码 + 一句话，不展开。教程讲「怎么做」，博客讲「我以为会怎样，实际怎样，为什么」 |

被砍掉的内容在聊天里告诉学习者砍了什么、为什么。

### 结构

1. **先看成品**：真实的终端输出 / 响应，原封不动。删减必须标注并链接完整版。真实输出里的细节是后文的伏笔。
2. **每节骨架固定**：现象 → 反转 → 机制（因果链，不是「因为参数太低」）→ 代价量化 → 修法 → 「**结论与发现**」一两句可带走的话。
3. **bug 写成故事**，重点是「为什么没被发现」。
4. **还不能上生产**：每条具体到「现在的代码在什么情况下会出什么错」+ 修法方向。记录里用「未测」「未计入」带过的项在这里升格为独立条目。这一节写得越狠，前面的数字越可信。
5. **写在最后**：只放读者不了解本项目也能直接用的规则，不放复述。末尾回扣论点，预告下一阶段并收回第一节的伏笔。
6. **延伸阅读**：每条链接对应正文引用过的东西——记录、trace、讲义、代码、上一篇。这是「数字可回溯」在结构上的体现。

### 数字溯源表

写完后在聊天里给学习者一张表：博客里的数字 / 来源文件。写的过程中任何一个数字拿不准就回去打开文件；原始会话里一个「三次都是 4800」的表述回查后是「两次 4800、一次 2312」，这类错误一个就够毁掉全文可信度。记录里的口径说明（例如「不含 extract_result」）原样保留在博客里。

## 2. 博客：把方法论讲给学习者

博客写完后，在聊天里按下面的顺序逐步讲，每步指向博客里的具体位置：

1. 这篇的一句话是什么，为什么选它，标题和开头怎么从它长出来。
2. 证据怎么挑的，砍掉了什么。
3. 为什么开头放真实成品，删减处怎么标注。
4. 拿一节做例子，拆出「现象 → 反转 → 机制 → 代价 → 修法 → 结论」。
5. 拿一个 bug 做例子，强调「为什么没被发现」那一段的价值。
6. 数字溯源表，以及写的过程中纠正过的数字。
7. 「还不能上生产」怎么写才有信用。
8. takeaway 的筛选标准。
9. 一份下次自查清单（一句话论点？真实成品？每节有预期？每个 bug 有「为什么没发现」？每个数字有出处？不能上生产具体到触发条件？takeaway 无复述？有没有只为展示而贴的代码？）。

## 3. 复盘

### 五个带数字的发现

| 发现（一句话结论） | 证据（具体数字） | 来源文件 |

不是功能列表，是「用自己的数据证明了什么」。面试时可直接讲。

### 遗留债务

从 `PROGRESS.md` 债务清单和各记录的「待修」「未覆盖」汇总，每条：问题 + 触发条件 + 修法方向 + 预计在哪个阶段还。

### 模块去向表（带走什么）

| 本阶段模块 | 在下一阶段的角色 | 处理（直接用 / 改造 / 换形态 / 搁置到 Phase X） |

这张表让学习者明白下一阶段不是新项目，是同一条主线加一层。

### 方法层面的收获

除了技术，点出学习者在**做实验的方法**上的进步（开始用「两个参数跑出一样的数字」怀疑实验设计；开始看 trace 而不是看答案）。这是比任何功能都持久的东西。

## 4. 更新路线图

`learning/ROADMAP.md`（和 canvas，若有）：

- 本阶段标记完成，折叠；下一阶段标记进行中，展开。
- 现状盘点表：本阶段补齐的能力改为「已具备」，写上证据；还没还的债在对应行标「待修」。
- 顶部统计：阶段完成数、当前阶段、里程碑完成数。
- 新增「Phase N 回顾」节：五个发现表 + 债务 + 去向表。
- 里程碑：本阶段的打勾，下一阶段第一条改为进行中。
- 页脚：制定日期不动，加「最后更新 + 原因」。

## 5. 预热下一阶段

三段，不超过一屏：

1. **核心认知一句话**：下一阶段和本阶段的关系（「MiniCode 不是新项目，是给同一个循环换一套工具集」）。
2. **真正的工作量在哪三处**：直接点出最难的模块和它为什么难，以及本阶段哪条债务会在那里被放大。
3. **第一步**：下一阶段第一讲的验收是什么，小到一天能做完。

结尾：「准备好了说『指导我做完 Phase N+1』。」

更新 `learning/PROGRESS.md`：当前阶段 +1，讲次清零，`next_action: lecture`，债务清单保留并标注来源阶段。

## 发送前自检

1. 博客每个数字都能在溯源表里指出文件？口径说明保留了？
2. 「先看成品」是真实输出，删减有标注？
3. 「还不能上生产」每条具体到触发条件？记录里「未测」的项都升格了？
4. 方法论讲解的九步都对应到博客里的具体位置？
5. 复盘的五个发现都带数字和来源？
6. ROADMAP / canvas / PROGRESS 三处状态一致？
7. **与上一阶段的博客和复盘对比，哪一节更薄？为什么？**
